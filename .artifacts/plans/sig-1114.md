# SIG-1114 — Coach authoring screen: own courses, badges, submit-for-review

## Goal

Coaches opening `/courses/admin` get their own authoring workflow instead of the
admin's publish workflow: they see only their own courses with translated status
badges and the rejection note, edit tier/price/author name, and use "Save draft"
+ "Submit for review" (wired to the SIG-1113 server actions). Admins keep the
exact current behavior. Done means: all acceptance boxes checkable —
`visibleActions` matrix test, price helper edge tests, rejected-note save/resubmit
test, i18n alignment green, anonymous-redirect e2e green — plus
`npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build` clean.

## Scope

**In:**
- `src/courses/author-actions.ts` (new pure helpers) + `author-actions.test.ts`
- `src/i18n/course-admin-strings.ts` new EN+PT-BR keys (alignment test covers them)
- `src/courses/publish.ts`: `currentUserRole()` server action; tier/price
  validation in `checkedCourse` with a new `invalidPrice` error key
- `src/courses/store.ts`: new `fetchAuthorCourses({ userId, role })`;
  `fetchPublishedCourses` **untouched** (catalog path in `use-courses.ts`)
- `src/courses/use-admin-session.ts`: role-aware gate (author, not publish),
  exposes `role`; coach import path uses `saveCourseDraft`
- `src/courses/CourseFields.tsx`: tier select, price field (paid only),
  author name, `readOnly` prop
- `src/courses/AdminView.tsx`: badges, rejected-note panel, role buttons,
  in_review read-only, wiring to `saveCourseDraft`/`submitCourseForReview`
- `e2e/coach-authoring.spec.ts`: anonymous-visitor redirect only

**Out:** admin review queue + catalog tier badge (SIG-1115); access enforcement
(payments phase — tier/price are shown, not enforced); component/e2e tests for
signed-in coaches (no auth harness; covered by unit + server-action tests);
`review_note` editing (server-owned, set only by `rejectCourse`).

## Phase 1 — Pure helpers + tests (`author-actions.ts`)

New file, no I/O, following the `status.ts` grain (pure, `status.test.ts` pins it).

- `visibleActions({ role, status })` →
  `{ saveDraft, submitForReview, publish, unpublish, delete }` booleans:
  - coach (own courses only, so `isOwner` is implied `true`): `saveDraft` and
    `submitForReview` iff status is `draft`|`rejected`; `publish`/`unpublish`
    always false; `delete` iff `draft`|`rejected` (never published/in_review).
  - admin: `saveDraft` true, `publish` true, `unpublish` iff `published`,
    `delete` true, `submitForReview` false (admin approves directly).
  - anyone else: all false.
- `priceToCents(input: string): number | null` — trim; accept `19,90`,
  `19.90`, `19,9` (last separator is the decimal, others are thousands);
  max 2 decimals; `null` for empty/`abc`/`0`/negative. `1990` (no separator)
  means 1990 cents, not reais.
- `centsToPrice(cents: number, locale: SiteLocale): string` — `1990` →
  `19,90` (pt-br) / `19.90` (en), locale-explicit per `format.ts` grain.
- `validateTierAndPrice(tier, priceCents)` — `paid` requires positive-int
  cents, non-`paid` requires `null`; returns `{ ok }` or the
  `course.admin.error.invalidPrice` key.
- Test (`author-actions.test.ts`, `node:test` + `assert/strict`): full
  role×status matrix (coach never gets `publish`, admin does), price edges
  (`"0"`, `"19,9"`, `"abc"`, price-on-free, paid-without-price), round-trip
  `centsToPrice(priceToCents(x))`.

Considered and rejected: putting `visibleActions` in `status.ts` — that module
is the server transition matrix; button visibility is UI policy and deserves
its own module per the issue's target files.

## Phase 3 — Data layer (role + own-courses query)

- `publish.ts`: add `currentUserRole(): Promise<Role | null>` — same
  `createServerSupabase` + `getRole` pattern as `currentUserCanAuthor` (SIG-1060
  grain; server-side read, so no RLS concern). Reuse, don't invent a client
  role read.
- `store.ts`: add `fetchAuthorCourses({ userId, role })` — admin runs the
  current query unchanged; coach adds `.eq("created_by", userId)` on top of the
  `COURSE_SELECT_FIELDS` select (defense in depth over the RLS own-drafts
  policy). Do NOT modify `fetchPublishedCourses` (catalog consumers).
- `use-admin-session.ts`: gate on `currentUserCanAuthor()` + expose `role`
  from `currentUserRole()` (single parallel fetch); coach branch calls
  `fetchAuthorCourses`, admin branch keeps today's list; `importLocalDraft`
  role-branches to `saveCourseDraft` (coach) vs `publishCourse` (admin).
- Tests: extend `publish.test.ts`-style fake-Supabase coverage — coach
  `saveCourseDraft` with price-on-free fails `invalidPrice`; paid without price
  fails; valid paid saves `price_cents`. (Store-query filter itself is a thin
  Supabase chain; assert at the action level, matching existing conventions.)

`checkedCourse` gains the tier/price check via `validateTierAndPrice` so both
`saveCourseDraft` and admin `publishCourse` reject price/tier mismatches
instead of hitting the DB `courses_paid_price_check` as `publishFailed`.

## Phase 4 — `CourseFields` (tier / price / author)

Add after the pieces select, following existing label+input grain:
tier `<select>` (free/premium/paid), price text input rendered only when
`paid` (reais string in, `priceToCents` on save; `validateTierAndPrice` blocks
submit), optional author display name (≤120 chars, trimmed). New `readOnly?`
prop disables all inputs when true. Client-side tier/price errors surface
through the existing `setError({ key })` slot in `AdminView`.

## Phase 5 — `AdminView` (badges, note, role buttons, read-only)

- Sidebar list item: title + translated status badge (`draft`…`archived`);
  rejected item also surfaces that a note exists.
- Form area: when `draft.status === "rejected"` and `reviewNote` is present,
  a prominent note panel (`reviewNote.heading` + note text) above the fields.
  Note is server-owned: `saveCourseDraft` already preserves it (SIG-1113
  "clears nothing else", pinned by `publish.test.ts`).
- Buttons from `visibleActions({ role, draft.status })`: coach gets Save draft
  (→ `saveCourseDraft`, same validation/normalize flow as today's `save()`)
  + Submit for review (→ `submitCourseForReview`, disabled unless
  draft/rejected, refreshes list status to `in_review`); Publish/Unpublish/Delete
  render only per the matrix (coach never sees Publish; admin path unchanged).
- `in_review` (coach): `readOnly` fields + `inReviewNotice` explanation;
  chapter add/remove/upload buttons disabled.
- Keep the `previewDrafts` dev branch working (add role-agnostic defaults).

## Phase 6 — e2e anonymous redirect

`e2e/coach-authoring.spec.ts`: unauthenticated `GET /courses/admin` redirects
to `/courses` (page-gate behavior via `currentUserCanAuthor`, not the gated
sign-in button). No credentials → runs in CI. Run
`npx playwright test coach-authoring` (full suite is heavy; targeted run plus
`npm run build` covers the rest).

`npm test` · `npm run lint` · `npx tsc --noEmit` · `npm run build` ·

## Risks

- Browser RLS already scopes coach reads (own drafts + all published), so the
  explicit `created_by` filter is what actually delivers "own courses only" —
  verify by reading the query, not by manual UI (no coach seed in CI).
- `priceToCents("1.990")`: ambiguous thousands-vs-decimal — rule (last
  separator = decimal) is pinned by test; document it in the helper comment.
- `checkedCourse` change affects admin `publishCourse` too — intended
  (consistent validation), covered by existing publish tests.
- `importLocalDraft` role branch: coach path must use `saveCourseDraft` or a
  coach would hit the admin-only `publishCourse` gate — covered by wiring
  review, not by unit test (client hook).

## Assumptions

- Feature slice (c), not a bug; all "Decision (already taken)" items settled
  (tier/price shown-not-enforced; coach sees own rows only; no coach
  Publish/Unpublish/Delete-of-published; in_review read-only).
- `visibleActions` omits `isOwner`: the coach list contains own courses only,
  so ownership is implied; admin bypasses it.
- Coach delete limited to own `draft`/`rejected` ("no … Delete of published
  courses" implies non-published own delete stays, matching
  `removePublishedCourse` owner semantics).
- Anonymous redirect target is `/courses` (server page gate), not the gated
  sign-in button.
- `in_review` = fully non-editable inputs (narrowest read of "read-only").
- `1990` without separator = 1990 cents, not R$1990.
- Triage claims re-verified on current branch (`861278b`): AdminView actions at
  `:201-258`, `use-admin-session` admin-only gate at `:85`,
  `fetchPublishedCourses` unfiltered at `store.ts:164-192`, no tier/price UI,
  `saveCourseDraft`/`submitCourseForReview` present (SIG-1113), no
  `author-actions.ts` / `visibleActions` / price helpers / coach e2e spec.
