# SIG-1179 — Never show a user a puzzle they have already seen

## Goal

Every puzzle served in the regular Puzzles modes (rated, streak, rush, daily-excluded, Trainer, any theme) is one the user has never attempted before, across themes and across sessions/reloads/devices for logged-in users (best-effort local history for anonymous users). When the pool for a theme/rating range is exhausted, the UI shows a clear empty state instead of silently repeating. Done means: solve/fail/give-up puzzle X → X never served again in any theme or after reload; migration with RLS; unit + e2e coverage; `tsc`, lint, full test suite clean.

## Scope

**In:**
- New `public.puzzle_seen` table + RLS + index (migration), `Database` type entry, RLS-contract test pin.
- New server-side exclusion path so large seen histories never ship to the client (`puzzles_unseen` RPC + authenticated route usage).
- Client seen tracking: record at attempt-commit time, seed session exclusion at init, refetch-on-thin in `nextPuzzle`, anonymous localStorage history with login merge.
- Remove the silent-repeat fallback in `rankedPuzzles` / `pickPuzzle`; add an `exhausted` session state + empty-state UI with i18n (EN + PT).
- Unit tests (selection/exclusion, seen store, RPC/migration contract) + e2e (solve → not served again across themes + reload).
- Document the exact "seen" rule in code (attempt = solve, fail, or give-up; display-only doesn't count).

**Out:**
- Daily mode stays date-keyed (shared daily puzzle by design); mistakes SRS mode (`mistakes`) untouched per SIG-1097.
- No changes to rating/XP/motif logic, no catalog data changes, no PR-opening step.

## Background (verified understanding)

- `src/puzzles/use-puzzle-session.ts`: `exclude` is a `useRef(new Set())`, empty on mount, reset in `retry()` and on mode/theme change; fed only with ids shown since mount. Nothing persists it.
- `pickPuzzle` → `rankedPuzzles` (`src/puzzles/engine.ts:128-140`): filters by `exclude` but falls back to the full themed list when all are excluded (`fresh.length > 0 ? fresh : themed`) — silent repeat by design.
- `loadWindowedCatalog` → `GET /api/puzzles?exclude=` → `puzzles_window(p_exclude)` already supports exclusion, but callers only ever pass the session set. `nextPuzzle` never refetches — it picks from the one 50-row `catalogRef` loaded at init.
- `puzzle_progress.history` is capped at 20 entries (`engine.ts:348-357`, `normalizeHistory`) with a 256 KB jsonb cap — a recent-activity feed, not a seen ledger; cannot substitute.
- Auth pattern: `progress.ts`/`mistake-exercises-store.ts` do local-first hydrate + direct browser-Supabase upserts with owner-marker guards; RLS is own-rows via `(select auth.uid())`. `/api/puzzles` uses the cookie-free public client (no auth), so server-side seen filtering needs an authenticated path.

## Phases

### Phase 1 — Database: `puzzle_seen` table + `puzzles_unseen` RPC

**Changes:**
- New migration `supabase/migrations/20261031HHMMSS_puzzle_seen.sql` (check latest timestamp prefix in `supabase/migrations/` first; must sort after `20261025000000_size_limits_and_quotas.sql`):
  ```sql
  create table if not exists public.puzzle_seen (
    user_id uuid not null references auth.users (id) on delete cascade,
    puzzle_id text not null,
    seen_at timestamptz not null default now(),
    primary key (user_id, puzzle_id)
  );
  create index if not exists puzzle_seen_user_idx on public.puzzle_seen (user_id);
  alter table public.puzzle_seen enable row level security;
  create policy "puzzle_seen_select_own" ... for select using ((select auth.uid()) = user_id);
  create policy "puzzle_seen_insert_own" ... for insert with check ((select auth.uid()) = user_id);
  -- no update/delete needed (insert-only ledger; upsert by PK); grant select, insert to authenticated
  ```
  Follow the `puzzle_progress` migration shape (wrapped `(select auth.uid())`, own-row policies, grants to `authenticated` only).
- Extend the same migration (or a second one) with `public.puzzles_unseen(...)` RPC mirroring `puzzles_window` (security invoker, `set search_path = ''`, limit clamped 1–200, seed-stable `md5(id || seed)` order) plus an anti-join:
  `and not exists (select 1 from public.puzzle_seen s where s.user_id = (select auth.uid()) and s.puzzle_id = puzzles.id)`.
  Grant execute to `authenticated` only (anon has no uid; anon uses local history).
- Add the `puzzle_seen` table + `puzzles_unseen` function entries to `src/lib/supabase/database.types.ts` (mirror the `puzzles`/`puzzles_window` entries).
- Pin in `src/lib/supabase/rls-contract.test.ts`: table has PK `(user_id, puzzle_id)`, user index, own-row select/insert policies with wrapped auth check, no anon grant, RPC is security invoker with empty search_path and the anti-join clause.

**Tests/proof:** `npx tsx --test src/lib/supabase/rls-contract.test.ts` (or repo's test runner for that file); `tsc --noEmit`.

### Phase 2 — Seen store + record-at-commit + session wiring

**Changes** (new file `src/puzzles/seen.ts`, modeled on `src/lib/mistake-exercises-store.ts` + `src/puzzles/progress.ts` owner-marker pattern):
- `PUZZLE_SEEN_KEY = "xadrez-digital.puzzles.seen"` (+ owner key) in `src/lib/local-cache.ts`; add both to `USER_LOCAL_CACHE_KEYS` so account-switch purge covers them.
- `seen.ts` exports: `loadSeenIds(): Set<string>` (anon local set, cap ~2000 ids oldest-evicted… simplest: cap array length on write), `recordSeen(puzzleId, userId)` — fire-and-forget `upsert({user_id, puzzle_id}, onConflict user_id+puzzle_id)` via `createBrowserSupabase()` when logged in, always append to local set as fallback; `mergeLocalSeenToAccount(userId)` — batch-upsert local ids on login then keep local copy (harmless duplicate source).
- `use-puzzle-scoring.ts` `commit()`: after `applyScore` succeeds, call `recordSeen(currentPuzzle.id, currentUserId)` for every mode except `mistakes` and except `daily` (daily is date-keyed; record or not — decision: do NOT record daily, document it). Needs the user id: thread it from `usePuzzleSession` (which already resolves `userId` at init) into scoring via a ref/setter, or call `recordSeen` from session `commit()` instead — prefer the latter (one call site, `use-puzzle-session.ts:commit`, covers solve/fail/give-up since all funnel through it).

- `engine.ts` `rankedPuzzles`: remove the `fresh.length > 0 ? fresh : themed` fallback — return the fresh-sorted list (possibly empty). Update `pickPuzzle` (already returns null on empty) and fix `catalog-expanded.test.ts` expectations that rely on the fallback.

### Phase 3 — Authenticated serving path (no full-history download)

**Tests/proof:** extend `app/api/puzzles/route.test.ts` (authenticated request excludes seen rows via mocked RPC; unauthenticated unchanged; fallback intact). Run route tests + `tsc`.

## Risks

- **Race: record-then-serve.** `recordSeen` is fire-and-forget; a fast Next-click could serve X again before the upsert lands. Mitigation: `exclude.current.add(id)` synchronously at `showPuzzle` time (already done) + server RPC as the cross-session backstop; e2e asserts across reload, not within the same tick.
- **`rankedPuzzles` fallback removal** changes a shared helper — audit callers (session + tests only) and keep the sort contract identical.
- **Anonymous cap eviction** (~2000 ids) can theoretically re-serve very old anon sees; acceptable best-effort per the issue, documented in code.
- **Migration ordering**: new migration filename must sort last; verify with `ls supabase/migrations`.
- **RLS on new RPC**: `puzzles_unseen` must be security invoker (like `puzzles_window`) so caller RLS on `puzzle_seen` applies; anon must NOT get execute (would error on `auth.uid()` null — route only calls it when authenticated).

## Assumptions

- "Seen" = attempted (solved, failed, gave up) recorded once at commit time; merely displayed puzzles don't count (matches issue's "shown and attempted").
- Daily puzzle stays date-keyed; mistakes SRS mode untouched (issue's out-of-scope note).
- Reporter is the project owner; symptom taken at face value (code trace fully explains it; no competing hypothesis).
- Triage suggestion of a `puzzle_seen(user_id, puzzle_id)` ledger adopted; jsonb-history and full-exclude-param alternatives rejected for scale reasons above.
- Server-side exclusion via authenticated RPC preferred over shipping id arrays (issue's "don't load the full history to the client").
- Exhaustion UX = empty state (not silent rating-widen beyond the existing 4-window widening, which stays).
